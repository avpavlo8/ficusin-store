# Чат сайта

Покупатель пишет сотруднику в быстром окне поверх любой страницы магазина, без обязательной регистрации. Все действия «Написать нам», «Написать в чат» и вопросы об уходе/заказе открывают это окно без перехода со страницы. Полная история находится в разделе «Сообщения» личного кабинета (`/account/chat`). Старая ссылка `/chat` открывает быстрый чат. При сворачивании окна черновик сохраняется до перезагрузки страницы. Ссылки на социальные профили сохраняются как социальные ссылки.

Интерфейс переписки оформлен по просьбе владельца в стиле Telegram: голубые действия, светлый фон, белые и светло-зелёные сообщения, компактная шапка, время и галочки прочтения. Быстрое окно и кабинет используют одну серверную переписку. VisualViewport позволяет сохранить поле ввода в видимой области при уменьшении окна и появлении клавиатуры.

Сотрудники отвечают в `/admin?section=chat`. Право `chat.manage` доступно владельцу, администратору и менеджеру; роль проверяется сервером на каждом запросе. В меню виден общий счётчик непрочитанных сообщений. Входящие можно искать по имени, номеру обращения и тексту, фильтровать по открытым/решённым и просматривать страницами по 50. Решённое обращение открывается после нового сообщения. Отдельного обещания времени ответа или фиктивного статуса «онлайн» нет.

## Хранение и доступ

`support_conversations`, `support_messages`, `support_consents` находятся в PostgreSQL. Контейнерные перезапуски не удаляют историю или фотографии. Гостевой доступ — 32 случайных байта в HttpOnly/Secure/SameSite=Lax cookie `ficusin_chat_session` сроком на год; база хранит только SHA-256. Просмотр окна создаёт cookie, но не пустую переписку. Первая запись требует отдельного согласия; версия политики, время, IP и user agent записываются в одной транзакции с первым сообщением.

После входа история текущего браузера связывается с аккаунтом. Если у аккаунта уже есть чат, обе истории и свидетельства согласия объединяются. После выхода гостевая cookie не открывает историю аккаунта. На чужом устройстве без входа история недоступна. После удаления cookie неавторизованный посетитель теряет доступ; интерфейс предупреждает об этом. Учётная запись сохраняет доступ на других устройствах.

Сообщения и фото доступны только участнику и сотрудникам с `chat.manage`. Фото нельзя получить по одному ID без доступа к переписке. На API — `Cache-Control: no-store`, на HTML чата — `noindex`. Внешним мессенджерам ничего не отправляется. Оповещения — счётчики на сайте и в админке; фоновые push, SMS и email для чата не подключены. Содержимое переписки и cookie не пишутся в localStorage.

## Обмен и ограничения

Открытая видимая переписка обновляется каждые 4 секунды; входящие — каждые 5; счётчики — каждые 15. Скрытая вкладка или свёрнутое окно приостанавливают обновление переписки. При возвращении клиент загружает новые сообщения через `?after=<последний ID>`, последовательно по 50, пока не догонит историю: даже после более 50 ответов разрыва нет. Предыдущие страницы загружаются через `?before=<первый ID>`. Прочитанным считается входящее сообщение, нижняя часть которого реально видна одновременно внутри области сообщений и окна браузера. Скрытое окно или переписка ниже экрана не отправляют ложное прочтение. Курсоры ограничены существующими ID; будущие сообщения не могут оказаться заранее прочитанными.

Текст — до 4000 символов, одна фотография на сообщение. Браузер принимает фото до 15 МБ, уменьшает длинную сторону до 1600 px, переводит в JPEG и удаляет EXIF. Сервер проверяет фактический формат JPEG/PNG, размер до 2 МБ и до 16 млн пикселей. SVG/произвольные файлы не принимаются. До 30 отправок в минуту с IP; это лимит одного экземпляра приложения, как у других публичных форм. При горизонтальном масштабировании лимитер нужно вынести в общее хранилище.

Каждое сообщение имеет `clientId`; уникальность `(conversation_id,sender,client_id)` делает повтор после обрыва сети безопасным. При ошибке текст и фото остаются в форме. Ctrl/Cmd+Enter отправляет сообщение; Enter добавляет строку. Вопрос из карточки, статьи или заказа добавляет ссылку на исходную страницу, которую покупатель может убрать перед отправкой.

## API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/v1/chat` | Собственная переписка; `?before=<messageID>` для истории, `?after=<messageID>` для обновления |
| POST | `/api/v1/chat/messages` | `{clientId,text,image?,consent,contextUrl?,contextLabel?}` |
| POST | `/api/v1/chat/read` | `{through:<последний видимый ID>}` |
| GET | `/api/v1/chat/unread` | `{unread:number}` |
| GET | `/api/v1/chat/photos/{messageID}` | Приватное изображение |
| GET | `/api/v1/admin/chat` | `?status=open|closed&q=...&offset=0`; `{items,hasMore}` |
| GET | `/api/v1/admin/chat/unread` | Общий счётчик для сотрудника |
| GET | `/api/v1/admin/chat/{id}` | Переписка; `?before=...` |
| POST | `/api/v1/admin/chat/{id}/messages` | Ответ сотрудника |
| POST | `/api/v1/admin/chat/{id}/read` | Прочтение сотрудником |
| PATCH | `/api/v1/admin/chat/{id}` | `{status:"open"|"closed"}` |
| GET | `/api/v1/admin/chat/{id}/photos/{messageID}` | Приватное изображение для сотрудника |

Ответ переписки: `{id,status,customerReadId,staffReadId,messages,hasMore}`. Сообщение: `{id,sender,text,contextUrl?,contextLabel?,hasImage,createdAt}`. Тело JSON ограничено 3 МБ. Невалидные сообщения/отсутствие согласия дают 400, нет сессии сотрудника — 401, недостаточно прав — 403, чужое фото — 404, превышен лимит — 429, ошибка хранилища — 503.

## Проверки и выпуск

`go test ./...`, `go vet ./...`; PostgreSQL-тесты: `CHAT_TEST_DATABASE_URL=... go test -race ./internal/chat ./internal/httpapi -count=1`. Изолированные схемы удаляются после теста. CRM acceptance также запускает эти проверки в PostgreSQL.

`e2e/tests/chat.spec.ts` проверяет сбой/повтор, сохранение текста, контекст и переходы на desktop/iPhone/Android. `e2e/verify-chat-acceptance.mjs` проверяет настоящий Go + PostgreSQL в Chromium и WebKit: сообщения в обе стороны, фото, прочтение, перезагрузку, изоляцию доступа, закрытие и повторное открытие, отсутствие переполнения. Используются только локальные/CI пользователи. Скрипт не предназначен для production.

Миграция `20261022_site_chat.sql` применяется автоматически. При откате приложения таблицы нужно сохранить, чтобы не потерять переписку; не удалять миграцию из журнала и не переименовывать её. Возврат предыдущего приложения временно уберёт интерфейс, но оставит данные для повторного выпуска.
