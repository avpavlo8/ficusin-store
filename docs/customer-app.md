# Клиентское приложение и вход в управление

Верхняя панель магазина разделяет два назначения: иконка человека/аватар ведёт прямо в клиентский кабинет (`/account`, для гостя — вход с возвратом туда), отдельная иконка панели управления доступна только manager/administrator/owner и ведёт в `/admin`. Выход из аккаунта остаётся в клиентском кабинете. Логотипы в админке открывают магазин. Нижняя ссылка «Открыть магазин» и рекламный блок установки в админке удалены; отдельный admin manifest и технический захват install prompt сохранены.

Раздел «Приложение» в `/account/profile` содержит установку и настройки уведомлений. Это ручной доступ, поэтому он остаётся видимым независимо от первого предложения на главной и возможностей браузера. Неподдерживаемый браузер, необходимость установки на iPhone, выключенный сервер push и запрет разрешения показываются явно, а не скрывают весь раздел.

Настройки заказов и клиентских сообщений — отдельные переключатели. Они сохраняют независимые opt-out cookie, используют общий browser push subscription и не отписывают устройство целиком при выключении одного канала. Orders изменяет только `/push/subscribe` или `/push/unsubscribe`; chat — только клиентский `/chat/notifications`. Staff-chat не используется. Системное разрешение запрашивается только внутри явного нажатия переключателя, до сетевых ожиданий. На iPhone вне установленного приложения сначала показывается инструкция установки.

На главной первый визит показывает нативное модальное предложение «Фикусин на экране Домой». Ключ `ficusin:install-offer-seen:v1` сохраняется в localStorage при показе, поэтому закрытое предложение не всплывает повторно; StrictMode/visibility callbacks не создают повторный показ. Установленное приложение не получает предложение. Без доступного хранилища используется безопасный fallback на один показ за жизнь страницы. Предложение не перехватывает уже открытый modal/chat/menu. Оно не вызывает системный install prompt само: кнопка «Установить» использует сохранённое событие браузера, иначе доступны инструкции. На других страницах спонтанные install-подсказки удалены.

Гость с загруженной сессией видит баннер накопительной скидки в корзине с товарами и при оформлении заказа. Он объясняет скидку на следующие покупки, а не обещает немедленное снижение текущей цены. Ступени соответствуют `internal/order/loyalty.go`: каждый 10 000 ₽ выполненных заказов добавляет 1%, максимум 10%. Ссылки входа/регистрации сохраняют текущий returnTo; корзина остаётся серверной. При неизвестном состоянии сессии или ошибке проверки цены баннер не притворяется гостевым.

Проверки: `frontend/tests/app-discovery.test.mjs` — четыре теста одноразового показа, установленного приложения, storage failure и независимых endpoint каналов; frontend lint/typecheck; обновлённые e2e fixtures `mockApi(...,{showInstallOffer:true})` включают предложение только в соответствующих сценариях. Остальные сценарии моделируют повторного посетителя. Реальные разрешения на устройстве и системная установка не запускались при локальной реализации.
