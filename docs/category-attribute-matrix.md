# Матрица атрибутов товарных категорий

Цена, остаток и SKU остаются данными SKU из существующих источников. Категория, название, основное фото и короткое описание — поля PRODUCT, а не динамические атрибуты. Этап 1 — критерий готовности контента; все перечисленные динамические поля пока необязательны для старых карточек.

## Этап 1

| Категория | PRODUCT | SKU / вариант | Фильтры | Badge | Характеристики |
|---|---|---|---|---|---|
| Растения | латинское название¹, освещение, полив, сложность ухода, безопасность для животных, размещение² | высота, диаметр технического горшка | высота, горшок, свет, полив, уход, питомцы, размещение | свет, полив, уход, питомцы | все заполненные поля этапа 1 |
| Кашпо | тип, материал, цвет, дренаж | внешний диаметр, высота | тип, материал, диаметр, дренаж | тип | все заполненные поля этапа 1 |
| Грунты | тип, назначение/группа растений, состав | объём или вес | тип, назначение, объём | назначение | все заполненные поля этапа 1 |
| Удобрения | форма, основа, назначение/группа, способ применения | объём или вес | форма, основа, назначение, объём | форма, назначение | все заполненные поля этапа 1 |
| Аксессуары | функциональный тип, совместимость, материал³ | необходимые размеры | функциональный тип; материал только при влиянии на выбор | функциональный тип | все заполненные поля этапа 1 |

¹ `latin_name` — обычное поле PRODUCT. ² Рекомендуется, но не требуется для старых карточек. ³ Не заполняется ради полноты, если не влияет на выбор.

## Этап 2

Влажность, скорость роста, цветение, pH, NPK, внутренний диаметр и другие расширенные размеры, декоративные характеристики и подробные рекомендации. Они остаются необязательными и не являются gate сохранения существующего каталога.

## Правила показа и расширения

- `filterable` включается только для покупательского выбора и только в своей категорийной ветке.
- `badge` используется для коротких различающих признаков, не для числового паспорта товара.
- `showInCharacteristics` допускается для заполненных полей этапа 1; этап 2 включается постепенно.
- PRODUCT описывает общую карточку; размеры, объём/вес конкретной продажи относятся к SKU, когда различаются между вариантами.
- Размер товара и размер упаковки не взаимозаменяемы; `package_*` остаются техническими.
- Расширение выполняется новым стабильным code и необязательным назначением на корневую категорию.
- Перевод в required допускается только после отчёта готовности данных и отдельного решения.

## Локализация и миграции

`value` — стабильный code, `label` — русское название из `attribute_options`. API сохраняет `value` и добавляет `displayValue`, `options` и `optionLabels`; multi-enum локализуется поэлементно. Неизвестный code возвращается как безопасный fallback. Нельзя заводить отдельные неполные словари во frontend.

Definitions, options и заполненные values не удаляются. Изменение справочника — upsert и деактивация. Backfill начинается с подсчёта строк и требует резервной копии; миграция этапа 1 backfill не выполняет и не меняет SKU, Saby IDs или category mapping товаров.
