# Перенос сохранённых планов каталога

Миграция `20261114_zzzz_catalog_plan_compatibility.sql` переносит только
редактируемые `catalog_editor_plans`. Она не отправляет запросов площадкам,
не меняет цены товара, внешние связи, остатки или статусы публикаций.

Для каждого изменённого плана исходный JSON сохраняется в неизменяемой
`catalog_plan_format_history`, вместе с контрольными суммами исходного и
канонического JSON. Повторный запуск не создаёт вторую копию.

Общий `marketplace.article` материализуется в `wb.article` и `ozon.article`.
Отсутствие и JSON `null` означали наследование в прежнем Go-читателе; теперь
они получают прежнее эффективное значение. Явная пустая строка остаётся пустой.
Неизвестные свойства JSON сохраняются. Некорректные скалярные значения вместо
объекта/артикула не исправляются догадкой и остаются видимыми в инвентаризации.

У плана без режима, но с сохранённой ценой WB/Ozon, устанавливается `manual`;
суммы не пересчитываются. Явные `auto`/`manual` сохраняются. Отсутствие и режима,
и сохранённых цен не превращается в ручную цену. Новые сохранения от прежнего
клиента проходят такое же преобразование до формирования новой публикации.

## Неизменяемые запросы площадок

`catalog_editor_publications.payload`, `fingerprint`, `progress`,
`pending_payload` и `pending_fingerprint` не обновляются этой миграцией.
Их артикул, штрихкод, task ID и сведения о неизвестном исходе доказывают
принадлежность внешней операции. Преобразование JSON могло бы нарушить эту
защиту, даже если внешний вид формы остался прежним.

Для этих данных сохраняется узкий читатель `Marketplace.SellerArticle` /
`Request.SellerArticle`. Это действующая граница формата, а не прежний обработчик
публикации. Удалять её можно только после сверки старых операций и перехода
на новый явно сохранённый запрос. Терминальный статус сам по себе недостаточен:
`SyncExistingEditorPlan` использует прежний подтверждённый запрос как источник
защищённых полей при следующем обновлении.

Инвентаризация после миграции не выводит артикулы, запросы или персональные
данные:

```sql
SELECT kind, count FROM catalog_compatibility_inventory ORDER BY kind;
```

`editable_noncanonical_plan` и `editable_invalid_shape` показывают оставшиеся
редактируемые данные. `frozen_shared_article`,
`pending_or_unknown_shared_article`, `pending_revision_shared_article` —
блокеры удаления читателя замороженного формата. Неизвестный результат требует
чтения площадки либо ручной сверки; его нельзя исправить сбросом receipt.

## История прежней выгрузки СБИС

Каждая строка `legacy_archive.catalog_saby_exports`, включая ошибки, неотправленные
и осиротевшие записи, копируется в неизменяемый
`catalog_external_operation_history`. Журнал содержит полный исходный JSON,
его SHA-256, ключ операции, состояние и исходный внешний ID. Миграция проверяет
полное совпадение копии перед заменой защит удаления.

Это историческое доказательство, а не подтверждение новой активной связи.
`product_external_ids` и `product_variants.saby_id` из него не заполняются.
Архив остаётся сохранённым. Действующие проверки удаления вариантов и черновиков
используют журнал; они больше не зависят от прежней таблицы выгрузки.

`saby_history_needs_reconciliation` — число операций, которые требуют сверки,
а не число автоматически исправленных операций. Более ранняя миграция
вывода прежнего экспортера по-прежнему блокирует обновление при активной или
неизвестной операции. Новый журнал не обходит этот запрет и не возобновляет
прежний exporter.

## Проверка

`TestCatalogCompatibilityMigrationPostgres` выполняет полный набор миграций в
отдельной пустой БД `ficusin_catalog_compatibility_test`, создаёт старые планы и
замороженные receipts и проверяет точное сохранение данных, защиту удаления,
новый writer и повторный запуск миграции. Тест отказывается работать с другим
именем БД или удалённым хостом. Локально используется порт 55440; CI допускает
порт 5432 только при `CI=true`.

Рабочие данные этой локальной проверкой не изменялись. Нулевые счётчики тестовой
БД не являются свидетельством отсутствия старых данных в production.
