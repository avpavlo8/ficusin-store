# Внешние интеграции

## Saby

Назначение: каталог, артикулы, базовые цены, остатки, изображения и в будущем склады/заказы.

Текущий запуск: GitHub Actions каждые 6 часов и вручную через workflow dispatch. Credentials Saby находятся в GitHub Secrets. Входящий endpoint защищён GitHub OIDC token, привязанным к репозиторию, `main` и конкретному workflow.

Переменные workflow: `SABY_POINT_ID`, `SABY_PRICE_LIST_ID`, `FICUSIN_SYNC_URL`.

Критические свойства:

- пустой каталог не должен архивировать все товары;
- импорт выполняется транзакционно;
- неизвестные/неопубликованные позиции фильтруются;
- повтор одного payload должен быть безопасен;
- ручной контент нельзя перезаписывать после внедрения локальных override-полей.

## SMS.ru

Назначение: подтверждение владения телефоном по схеме «пользователь звонит нам».

Secret: `SMSRU_API_KEY`.

Проверка живёт 5 минут, повторный запрос ограничен 45 секундами. Вход и регистрация — разные flow. Вход не создаёт нового клиента.

## СДЭК

Назначение: поиск городов и ПВЗ, расчёт доставки.

Credentials читаются из зашифрованной записи `integration_credentials`; private RSA key находится в `INTEGRATION_SECRETS_PRIVATE_KEY`.

Frontend-предложение не считается окончательным. При заказе backend повторно получает тариф и проверяет существование выбранного ПВЗ.

## Telegram

Назначение: уведомлять группу «Заказы Фикусин» о новых заказах.

Настройки: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ORDER_CHAT_ID`. Chat ID production: отрицательный идентификатор группы, но реальное значение не следует дублировать в новых документах или коде.

Сначала заказ фиксируется в БД. Неудачная отправка логируется и повторяется worker по заказам без `telegram_notified_at`.

## YooKassa

Статус: не подключена.

Зарезервированные переменные: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RETURN_URL`.

Перед включением обязательны:

- подтверждённый магазин и юридические страницы;
- создание платежа только backend;
- webhook с проверкой подлинности;
- идемпотентность по order/payment ID;
- состояния pending/succeeded/canceled/refunded;
- проверка суммы на backend;
- тестовый контур и сценарий возврата.

## Общие правила

- Никогда не отдавать credentials браузеру.
- Указывать timeout для каждого внешнего вызова.
- Отличать временные ошибки от окончательных.
- Повторные операции должны быть идемпотентными.
- Логировать provider, operation и correlation ID, но не секреты и персональные данные.
- Недоступность уведомления не должна уничтожать бизнес-операцию; недоступность расчёта цены/доставки должна блокировать неверный заказ.
