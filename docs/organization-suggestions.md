# Подсказки организаций при регистрации

Поиск доступен для оптового покупателя в поле «Название организации или ИНН». Название выбранной организации остаётся в поле поиска. ИНН, КПП и юридический адрес скрыты до выбора подсказки, затем показаны серыми, без ручного редактирования. При изменении поискового запроса реквизиты очищаются и снова скрываются. Для ИП адрес может содержать только населённый пункт.

## Подключение

1. Создать аккаунт DaData на https://dadata.ru/ и подтвердить почту. Создание аккаунта и принятие условий выполняет владелец.
2. Получить API-ключ в личном кабинете. Для подсказок нужен только API-ключ, не секретный ключ стандартизации.
3. Добавить `DADATA_API_KEY` в серверное окружение приложения (Timeweb, приложение 229223). Для локального Go-сервера — в его окружение. Не использовать префикс `VITE_`, не сохранять ключ в Git и не вставлять его в чат.
4. Выпустить эту версию после согласования и проверить поиск по реальной организации: название, ИНН, конкретный филиал/КПП, заполнение адреса, сохранение реквизитов и возврат с подтверждения звонком.

Провайдер: https://dadata.ru/api/suggest/party/. Интеграция использует серверный POST `suggest/party`, `count=7`, действующие организации и ИП. По документации на 22.10.2026 базовый лимит — до 10 000 запросов в день; условия аккаунта проверяются у провайдера. Платная подписка автоматически не подключается.

Наш маршрут: `GET /api/v1/organizations/suggest?q=...`, от 3 до 150 символов, не более 30 запросов в минуту на IP. Ключ хранится на сервере и не возвращается в браузер. В DaData передаётся только поисковый запрос, без контактных полей и телефона покупателя. В ответ нашего маршрута попадают только четыре поля реквизитов. Сырые ответы и запросы не пишутся в прикладной лог. Повторяющиеся ИНН с разными КПП сохраняются отдельными вариантами.

Без ключа маршрут возвращает `available:false`, форма сообщает о недоступности справочника. При ошибке/исчерпании лимита провайдера контактные поля сохраняются. Оптовая регистрация требует выбора организации из справочника; ввод реквизитов вручную не предусмотрен.

## Состояние локального превью

На `127.0.0.1:4182/register` работает изолированный пример: выбрать «Оптовый», ввести «Зелёный дом» или `0000000000`. Подсказки явно помечены как демонстрационные. Это не подключение к живой базе. Реальный провайдер не проверен: у владельца пока нет аккаунта/ключа. Серверный адаптер проверяется с HTTP-сервером теста, а выбор/ошибки/сохранение формы — браузерными тестами.
