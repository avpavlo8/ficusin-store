# Flowwow: каталог, цены и остатки

Flowwow — отдельный раздел панели управления рядом с Авито. Источник общего
контента — сайт: название, описание, порядок фотографий и `base_price_minor`
конкретного варианта. Общий текст WB/Ozon не подменяет текст сайта для Flowwow.
Цены отправляются в рублях с двумя знаками, скидка Flowwow устанавливается в 0,
чтобы цена покупателя совпадала с ценой сайта.

## Настройка

Секреты задаются только в окружении backend:

- `FLOWWOW_API_TOKEN` — Seller API bearer-токен;
- `FLOWWOW_SHOP_ID` — положительный числовой ID одного магазина.

Без них раздел работает с локальными подготовками и показывает отсутствие API.
Живые записи используют существующие ограничения публикации: одновременно
`CATALOG_PUBLICATION_MODE=live`, `APP_ENV=production` и
`CATALOG_PUBLICATION_LIVE_ENABLED=true`. Ни миграция, ни подключение ключа не
переводят старые `disabled`/`mock` подготовки в живую отправку: товар нужно
сохранить снова. Пустые ключи не означают успешный обмен.

Первая живая операция фиксирует ID магазина в `flowwow_shop_binding`. Его
последующая смена в окружении блокирует записи, чтобы старые артикулы не
обновили чужой каталог. Для другого магазина требуется отдельная миграция связей.

## Работа сотрудника

В каталоге открыть товар → «Маркетплейсы» → Flowwow. Для нового назначения
отметить «Отправлять в Flowwow», выбрать создание или привязку существующей
карточки. При привязке указать числовой ID и текущий артикул карточки Flowwow;
если артикул ещё не назначен, будет назначен артикул сайта. Список существующих
карточек доступен в разделе Flowwow, по 50 на страницу. По названию карточки
автоматически не сопоставляются.

Подкатегории и поля загружаются из официального API. UI поддерживает текст,
числа, флаги, единицы измерения, справочники, списки и состав. Общие поля, цена,
фото и складское количество не вводятся второй раз. Изменение подкатегории
существующей карточки запрещено протоколом Flowwow и блокируется до записи.
Готовые товары (`productType=2`) и дополнительные (`3`) не обслуживаются этим
первым каналом; реализованы обычные товары (`1`).

Сохранение товара включает Flowwow в существующий `editor-plan`. Для уже
связанного варианта обновление продолжается независимо от checkbox создания.
Статусы и ошибки видны в редакторе и отдельном разделе; повторная проверка
использует сохранённый результат предыдущей попытки.

## Протокол и сохранность

Официальная база API — `https://apis.flowwow.com`, область `shopId` передаётся
в query, токен — только в Authorization. Redirect запрещён. Основные вызовы:

- `POST /apiseller/products` — точный поиск по offerId/productId;
- `POST /apiseller/categories/tree`, `subCategoryProperties` — категории/правила;
- `POST /apiseller/products/create`, `update`, `offersMappings`;
- `PUT /apiseller/prices/put`, `stocks/put` — цены и остатки.

Flowwow update заменяет полный набор полей. Адаптер сохраняет разрешённые
текущей схемой внешние свойства и основные параметры карточки, затем применяет
значения сайта и настройки канала. Проверяются обязательность, альтернативные
поля, типы, значения справочников, единицы и числовые границы. Ошибки отдельных
товаров при HTTP 200 не считаются успехом. Фотографии — публичные HTTPS URL;
локальные, private IP и URL с паролями отклоняются.

До создания сохраняется подготовленный запрос, а перед POST — необратимая
граница в существующей очереди. Таймаут создания и истёкшая lease ведут к
поиску по тому же offerId. Если карточка не найдена, состояние
`needs_attention` запрещает слепое повторное создание. Уникальные ограничения
и проверка владельца ссылки не дают привязать одну карточку к двум вариантам.
Связи Flowwow живут в `catalog_editor_remote_links`, без попадания в WB/Ozon
или закупочные зеркала этих площадок.

После записи проверяются имя, описание, цена, скидка и количество фотографий.
Flowwow обрабатывает фото асинхронно до 30 минут; равное количество фото не
является проверкой совпадения содержимого изображений или модерации площадки.
Живой приём контента на конкретном аккаунте ещё нужно проверить с его доступом.

## Автоматические цены и наличие

Worker проверяет связанные live-варианты каждые 30 секунд. При изменении цены,
остатка или связи отправляет новые значения и читает карточку обратно. Состояние
и ошибки находятся в `flowwow_inventory_sync`; неудачи повторяются с задержкой.
Изменения цены из закупок или другого серверного пути тоже обнаруживаются,
даже если редактор товара не открывали.

Остаток повторяет правила витрины: активный опубликованный вариант, основной
активный склад, существующая номенклатура СБИС, включённое поле `stock`, данные
не старше двух часов, доступное количество с учётом проводок продаж через `order_sale_inventory`.
Старый остаток и выключенный вариант дают 0. Это не импортирует заказы Flowwow. Общая обработка заказов/отмен и
резервирование каналов остаются отдельной задачей.

Создание обычной карточки требует положительного свежего остатка: API create
не принимает `stock=0`. При нулевом остатке существующая карточка получает 0
через stocks/put; контент может требовать повторной отправки после пополнения,
если схема Flowwow не допускает заполнение полного update с нулевым stock.

Контент и складские записи одного варианта сериализуются PostgreSQL advisory
lock. Успешная отправка контента инвалидирует складской snapshot, чтобы после
неё повторно применить актуальные цену и количество. Ошибки контента не
останавливают обнуление остатка уже связанного товара.

## Проверки

- `go -C backend test ./...` — unit/HTTP tests, включая эмулятор Flowwow;
- `TestFlowwowPublicationLocalDatabase` на UTF-8 базе
  `ficusin_local_publisher_test`: чистые миграции, редактор → публикация → чтение,
  обновление без дубля, disabled/live изоляция, цены, свежий/устаревший склад;
- тест добавлен в PostgreSQL job CI и не считается выполненным без DB env;
- frontend lint/build и OpenAPI check;
- Playwright: отдельный раздел, фильтры, внешний каталог, сохранение настроек
  редактора на iPhone, Android и desktop.

Локальная проверка использует отдельный HTTP transport с тестовой категорией,
без сети и реальных секретов. Сам по себе mock не подтверждает права аккаунта
Flowwow, модерацию, публикацию карточки на витрине или принятие реальных фото.
