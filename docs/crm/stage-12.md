Этап является исследованием и проектом подключения. Он не создаёт приложение Avito, не сохраняет ключи, не публикует, не снимает и не возобновляет объявления. В качестве интерфейсного ориентира принят первоначальный макет `exec-cc5caf69-b255-4bdd-a213-d2a257ce7162.png`.

- Основная карточка и остаток остаются в СБИС; отдельный склад CRM не создаётся.
- Общая координация интеграций уже хранит задачи, lease, поколения, cooldown и `Retry-After`. Будущий адаптер Avito обязан использовать её, а не собственный worker.

## Предлагаемый безопасный контракт

1. Владелец запускает «Проверить доступ». Проверка читает профиль приложения и разрешённые возможности, ничего не публикует.
2. Объявления импортируются в локальное зеркало. Владелец вручную связывает каждое объявление с основной карточкой СБИС. Конфликт одной карточки Avito с двумя основными товарами блокируется.
3. Остаток читается из уже синхронизированной базы CRM. Нулевой остаток создаёт намерение `archive`, но внешняя запись разрешается только после подтверждения метода.
4. Появление остатка не возобновляет объявление автоматически. CRM показывает «Можно возобновить»; владелец подтверждает потенциально платное действие. Позже автоворонку можно включить отдельной настройкой с лимитом бюджета.
5. Каждая запись имеет устойчивый ключ `avito:<account>:<item>:<desired-state>:<stock-version>`, состояние `queued/running/unknown/reconciled/failed`, lease и сверку результата. Таймаут означает `unknown`, а не повторную публикацию.
6. `429` сохраняет `Retry-After`; серия кнопок объединяется в одну задачу. Фоновая задача не конкурирует с ручной.
7. Переход клиента на сайт получает серверную метку источника Avito. Оплаченный заказ сайта создаёт одну продажу `site` с атрибуцией `avito`, а не второе событие Avito. Личная карта не является запасным способом обхода кассы.

## Сценарии проверки будущей реализации

- Подтверждённый остаток стал 0: одна задача снятия; повтор окна не создаёт вторую.
- Остаток неизвестен или синхронизация СБИС устарела: объявление не меняется.
- Остаток вернулся: показывается предложение возобновить; без согласия владельца записи нет.
- `429`: задача ждёт `Retry-After`; другие каналы продолжают работать.
- Таймаут публикации: состояние `unknown`, затем чтение факта; слепого повтора нет.
- Два нажатия возобновления и два процесса: один бизнес-эффект благодаря lease/fencing.
- Объявление уже архивировано вручную: сверка завершает задачу без лишней записи.
- Смена связи сохраняет историю и не перепривязывает старые продажи.
- Оплата заказа по ссылке из Avito: один чек и одна продажа, источник Avito сохранён.
- Менеджер не видит ключи, связи, цены и кнопки публикации; прямой API отвечает 403.
- Desktop 1440 px и mobile 390 px: состояния «не подключено», «нет прав», `429`, устаревший остаток и частичный успех читаемы без одной лишь цветовой индикации.

После открытия портала разработчика нужна только безопасная проверка перечня доступных API/scopes и условий тарифа. Если нужные методы тарифу недоступны, рабочим вариантом остаётся официальный ручной кабинет Avito; скрейпинг не применяется.
