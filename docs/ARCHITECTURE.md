# Архитектура

## Контекст

`ficusin.ru` работает как одно развёртываемое приложение в Timeweb Cloud:

- браузер загружает React SPA;
- Go-процесс обслуживает `/api/v1/*`;
- тот же Go-процесс отдаёт собранные статические файлы;
- PostgreSQL хранит бизнес-данные;
- внешние системы: Saby, СДЭК, SMS.ru, Telegram и в будущем YooKassa.

Один контейнер выбран ради стоимости. Граница frontend/backend уже строгая, поэтому позже их можно развести без переписывания бизнес-логики.

## Компоненты

### Frontend

Путь: `frontend/`.

Ответственность: интерфейс каталога, корзины, оформления, входа, регистрации, кабинета и админки. Frontend вызывает только HTTP API и не знает строку подключения к БД или секреты интеграций.

### Backend

Путь: `backend/`.

- `cmd/api` — сборка зависимостей, migrations, HTTP server и фоновые worker;
- `internal/httpapi` — транспорт и валидация HTTP;
- `internal/auth` — клиенты, подтверждение звонка и sessions;
- `internal/catalog` — чтение опубликованного каталога;
- `internal/order` — серверная проверка и сохранение заказов, Telegram retry;
- `internal/integration` — СДЭК, SMS.ru, Telegram и защищённые credentials;
- `internal/saby` — нормализация и импорт каталога;
- `internal/admin` — read model админ-панели;
- `internal/store` и `internal/migrate` — PostgreSQL и migrations.

### PostgreSQL

Схема изменяется только файлами `timeweb/migrations/NNN_*.sql`. Migrations применяются Go-приложением до запуска HTTP server.

### CI/CD

GitHub Actions выполняет frontend lint/build, Go tests/vet/build и Docker build для каждого push и PR. Timeweb отслеживает `main` и разворачивает прошедшую проверку.

## Основные потоки

### Авторизация

1. Frontend отправляет телефон и flow в `POST /auth/request-code`.
2. Go нормализует телефон и запрашивает проверку у SMS.ru.
3. Клиент звонит на выданный номер.
4. Frontend опрашивает `POST /auth/verify-code`.
5. При регистрации создаётся клиент; при входе загружается существующий.
6. Go создаёт случайную session, хранит только SHA-256 token и выставляет HttpOnly-cookie.

### Заказ

1. Frontend отправляет корзину и способ доставки.
2. Go загружает актуальные варианты, цены и доступные остатки.
3. Для СДЭК Go повторно проверяет ПВЗ и тариф.
4. Заказ и позиции сохраняются транзакционно.
5. Telegram вызывается после commit; сбой не откатывает заказ.
6. Фоновый worker повторяет неотправленные уведомления.

### Saby

1. Scheduled GitHub Action получает данные Saby.
2. Workflow получает GitHub OIDC token.
3. `POST /integrations/saby/catalog` проверяет issuer, repository, branch и workflow.
4. Go нормализует до 2000 элементов и обновляет PostgreSQL транзакционно.
5. Не пришедшие Saby-товары архивируются.

## Ограничения текущей версии

- Product page, статьи, похожие и сопутствующие товары отсутствуют.
- Накопительные и оптовые цены ещё не участвуют в расчёте заказа.
- Оптовые минимумы хранятся, но не проверяются при заказе.
- YooKassa отключена.
- Админка преимущественно read-only.
- Saby-синхронизация пока перезаписывает описание и медиа.
- Списание/резервирование остатков при заказе не завершено.
