## Почему можно убрать старый экспорт СБИС

Новый общий редактор уже отправляет карточку через `SabyEditorPublisher`
и `catalog_editor_publications`. Он покрывает название, характеристики и
цену старого exporter, а также нативные категории/разделы, штрихкод, описание
и фотографии. Старый `/saby-export` не вызывается текущим UI. Производственная
старая таблица полностью пуста, поэтому в ней нет потерянных результатов,
ID или ожидающих отправок, которые потребовали бы продолжить обработчик.

Перед переносом таблицы новая миграция берёт эксклюзивную блокировку и
проверяет состояния заново. Если старое приложение успело поставить команду
после среза, миграция отказывается продолжать: сначала нужно завершить/сверить
её старым обработчиком. Терминальная история других окружений сохраняется в
`legacy_archive`, а защита ранее экспортированных SKU продолжает действовать.
Остатки isolated staging поддерживаются отдельно от удалённого exporter.

Состояние `needs_attention` нового СБИС не относится к пустой старой очереди.
Его нельзя «исправить» удалением receipt или возвратом CommerceML-процесса.
Срез не подтверждает успешную приёмку всех новых публикаций.

## Почему ручные предложения пока нужны

Текущий `frontend/src/lib/saveVariantEdits.ts` при изменении цены вызывает
`createManualPriceProposals`. Backend сохраняет пакет source=`manual` в
`procurement_action_batches` и отдельные каналы в `procurement_action_items`.
Эти же таблицы и ActionWorker обслуживают актуальные закупки.

Сравнение реализаций:

| Канал | Ручной/закупочный executor | Новый publisher |
|---|---|---|
| WB | Базовая цена `CompareAtValue` плюс рассчитанный discount | Округлённая итоговая `WBPrice`, discount=0 |
| Ozon | price и old_price | Только price в импорте карточки |
| Avito | Прямой UpdatePrice после подтверждения владельцем | Нет Avito в ChannelPublishers; XML-фид выключен в production и работает по другой цепочке |
| СБИС | XLSX и отдельная фиксация импорта | Нативный Update в явном editor Save/live-процессе |

Новый editor Save и старый вход изменения цены не эквивалентны по триггеру,
доступности и данным площадок. Старого UI подтверждения manual-пакетов больше
нет; сохранение backend не устраняет этот известный пробел. Создание новых
черновиков продолжается из текущего кода, поэтому удалить их генератор и API
без согласованной замены означало бы изменить действующую бизнес-логику.

Условие удаления: единый текущий процесс должен охватить все входы изменения
цены, согласованную модель old_price/discount и прямую цену Avito либо явно
согласованную замену Avito фидом. После этого остановить создание manual-пакетов,
сверить все отправленные operation IDs, завершить очередь, сохранить историю и
удалить только manual-ветку. Закупочные таблицы и worker остаются нужны.

## Повторная проверка перед выкладкой

Проверить состояния старой очереди до применения миграции; не снимать её
защиту ради деплоя. Новые `needs_attention`/`failed` проверяются через текущие
процессы восстановления. Не запускать реальные retry/create ради проверки
очистки. Слияние в main автоматически запускает production-деплой Timeweb;
эта работа выполнена только в `cleanup/unused-legacy-code`.
