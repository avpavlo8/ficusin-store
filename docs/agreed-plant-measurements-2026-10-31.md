# Согласованные замеры 31 октября 2026

Владелец подтвердил перенос всех замеров в переписке: 17 листов, 249 SKU.
Петунья 722 зачёркнута и исключена. Каждый SKU сопоставлен с актуальным
публичным API: 202 PRODUCT, 250 активных вариантов, все 249 нужных SKU найдены.
JSON рядом содержит согласованные значения и свежие ключи/имена/подписи сайта.

Миграция записывает 2239 числовых атрибутов: высоту, массу в граммах,
диаметр/ширину горшка и обе коробки. Размеры — длина × ширина × высота, см.
У двух тилландсий удаляется неверный диаметр; у флорариума 537 вместо диаметра
сохраняется отдельная ширина 20 см. 127 коробок одинаковы круглый год;
остальные имеют два сезонных варианта. Подтверждённые укладывающиеся растения
и исключения по размеру горшка сохранены без подгонки под коробки.

В 96 стандартных подписях D/высоты исправляются цифры, чтобы выбор размера
не показывал прежний замер рядом с новым. Словесные названия сохраняются.
Миграция не меняет цену, остаток, связи, статус публикации и выбранный сезон.

## Применение и проверка

- `python3 scripts/generate_agreed_measurements.py` воспроизводит SQL из JSON.
- Применение транзакционное: совпадают все 249 ключей SKU/ID/PRODUCT/имени/
  подписи/статуса либо пакет откатывается. На чистой БД без каталога — no-op.
- До изменения каждой позиции сохраняются прежние значения, источники,
  timestamps и подпись в `admin_audit_log`, action
  `variant.measurements.import.20261031`.
- В транзакции повторно читаются все записанные/удалённые атрибуты и
  проверяется сохранность остальных полей варианта.
- Повторное применение не перезаписывает последующие ручные правки.
- Интеграционный тест исполняет настоящий SQL: полный пакет, изменившаяся
  идентичность с атомарным отказом, пустой каталог, сохранность бэкапа,
  повтор после последующей ручной правки.

## Откат данных

Откат кода сам по себе не откатывает каталог. Перед обратным переносом
прочитать 249 записей указанного action. Для каждого кода в `after_data.attributes`
проверить, что текущее значение равно значению переноса. Если после переноса
значение изменяли, не перезаписывать его автоматически.
Для совпавших значений восстановить `before_data.attributes[code].value`,
`source`, `updatedAt`; если прежней записи не было — удалить созданное значение.
Аналогично восстановить `before_data.label`, только если текущая подпись равна
`after_data.label`. Выполнить в одной транзакции с отдельным аудитом отката.
Определение ширины горшка можно оставить: оно не меняет другие значения.
