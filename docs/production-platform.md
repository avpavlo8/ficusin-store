# Производственная платформа «Фикусин»

## Текущая схема

- исходный код: GitHub `avpavlo8/ficusin-store`;
- приложение: Timeweb Cloud App в московском регионе;
- база данных: управляемая PostgreSQL Timeweb Cloud;
- домены: `ficusin.ru` и `www.ficusin.ru`;
- production-сборка: один Docker-образ из корневого `Dockerfile`;
- runtime: один Go-процесс обслуживает API и статический React-клиент.

GitLab может оставаться зеркалом кода, но не является обязательной частью
запуска магазина.

## Окружения и выпуск

- изменения разрабатываются и проверяются локально в отдельной Git-ветке;
- отдельное постоянно оплачиваемое staging-приложение пока не используется;
- merge в `main` автоматически запускает production-деплой Timeweb; поэтому
  в `main` вливаются только PR с зелёными проверками и выполненным smoke-plan;
- Timeweb должен собирать Dockerfile, а не шаблон Express/Next.js;
- проверка состояния приложения: `GET /api/v1/health`.

## Данные и секреты

PostgreSQL — единственное постоянное хранилище пользователей, товаров, остатков,
заказов и настроек интеграций. CDEK и Telegram хранятся в БД в зашифрованном
виде; приватный ключ расшифровки задаётся только переменной окружения
переменными окружения (`CDEK_CLIENT_ID`, `TELEGRAM_BOT_TOKEN` и т. п.).

Saby вызывается из GitHub Actions. Его сервисные ключи остаются в GitHub
Actions Secrets, а Go API принимает каталог только с проверенным GitHub OIDC
токеном.

В репозиторий не добавляются пароли, токены, приватные ключи и строки
подключения к рабочей базе.

## Резервное копирование

- ежедневные автоматические бэкапы PostgreSQL средствами Timeweb Cloud;
- перед изменением схемы создаётся свежая копия;
- восстановление периодически проверяется на отдельной базе;
- фотографии после появления собственного хранилища должны храниться с
  версионированием.
