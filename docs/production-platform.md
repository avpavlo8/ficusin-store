# Производственная платформа «Фикусин»

## Текущая схема

- исходный код: GitHub `avpavlo8/ficusin-store`;
- приложение: Timeweb Cloud App в московском регионе;
- база данных: управляемая PostgreSQL Timeweb Cloud;
- домены: `ficusin.ru` и `www.ficusin.ru`;
- production-сборка: один Docker-образ из корневого `Dockerfile`;
- runtime: один Go-процесс обслуживает API и статический React-клиент.

GitLab может оставаться зеркалом кода, но не является обязательной частью
запуска магазина.

## Окружения и выпуск

- изменения разрабатываются и проверяются локально в отдельной Git-ветке;
- отдельное приложение `ficusin-staging` (Timeweb App 280757, 510 ₽/месяц)
  использует ветку `staging`, собственную логическую базу и отдельного пользователя;
- адрес: `https://avpavlo8-ficusin-store-1b1b.twc1.net`, доступ закрыт отдельным
  ключом; рабочие интеграции, клиенты и заказы туда не переносятся;
- перед выпуском обязательна успешная проверка того же кандидата на стейджинге;
- merge в `main` автоматически запускает production-деплой Timeweb; поэтому
  в `main` вливаются только PR с зелёными проверками и выполненным smoke-plan;
- Timeweb должен собирать Dockerfile, а не шаблон Express/Next.js;
- liveness процесса: `GET /api/v1/health`; readiness приложения и PostgreSQL:
  `GET /api/v1/ready`.

Если после merge workflow `Production smoke` не появился, выпуск нужно
повторно запустить через `workflow_dispatch` или новым проверенным merge:
проверка ожидает точный backend-хеш и frontend-бандл, а не только HTTP 200.

## Данные и секреты

PostgreSQL — единственное постоянное хранилище пользователей, товаров, остатков,
заказов и несекретных настроек интеграций. Секреты CDEK, Telegram, S3,
маркетплейсов и платёжных провайдеров задаются только переменными окружения.
Механизм `integration_credentials` удалён и не должен возвращаться.

Плановое чтение каталога и продаж Saby выполняют фоновые workers Go-приложения;
его сервисные ключи задаются в окружении backend. Общий редактор отдельно
использует подтверждённые native-запросы публикации. Ручной workflow GitHub
остаётся аварийным источником снимка: он использует Actions Secrets, а входной
маршрут Go проверяет привязанный к репозиторию/ветке/workflow OIDC-токен.

В репозиторий не добавляются пароли, токены, приватные ключи и строки
подключения к рабочей базе.

## Резервное копирование

- ежедневные автоматические бэкапы PostgreSQL средствами Timeweb Cloud;
- перед изменением схемы создаётся свежая копия;
- восстановление проверяется на отдельной базе ежемесячно с записью фактических
  RPO/RTO;
- собственные фотографии и private uploads хранятся в S3; резервирование,
  версионирование и сроки хранения объектов проверяются отдельно от PostgreSQL.
  Наличие настройки bucket само по себе не доказывает включённое версионирование.
