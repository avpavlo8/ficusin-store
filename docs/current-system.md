# Действующая система и границы очистки

Проверено по исходникам ветки очистки 13 ноября 2026. Эта карта описывает
состав приложения, а не состояние production-секретов, содержимое живой БД
или результат ещё не выполненного деплоя. Вход для нового агента — этот файл
и `AGENTS.md`; спецификация маршрутов — `openapi.yaml` и Go-router. Контракт
после снятия прежних API содержит 237 HTTP-операций; число проверяется
`check-openapi.mjs`, а не поддерживается вручную как источник истины.

## Как читать документацию

- Этот файл — карта текущего функционала, процессов и сохранённых зависимостей.
- Последний повторный аудит после переноса цен — [post-price-cleanup-audit.md](post-price-cleanup-audit.md).
- Тематические документы ниже объясняют действующие инварианты.
- Файлы с датой в названии, `docs/crm/stage-*` и `business-rules-v2-draft.md` —
  исторические решения/приёмка. Их баннер предупреждает, что описанный код мог
  быть удалён или заменён. Они сохраняют происхождение данных и решений, но не
  являются инструкцией повторно выполнить старую миграцию или вернуть старый UI.
- Миграции и связанные с ними JSON-источники не удаляются по возрасту. Чистая
  установка должна воспроизводить тот же каталог и ограничения целостности.

## Развёртывание и источники истины

Один Docker-образ собирает React/TypeScript/Vite, Go API, статические файлы,
шрифты PDF и SQL-миграции. Go обслуживает `/api/v1/*`, SEO-ответы и SPA-оболочку.
PostgreSQL хранит заказы, каталог, очереди, сессии и рабочие настройки. Публичные
фотографии и приватные вложения используют отдельные области S3.

`backend/cmd/api/main.go` собирает зависимости, применяет миграции, запускает
worker и затем публикует готовый router. Применённые имена записаны в
`schema_migrations`; миграции выполняются транзакционно по полному имени.
Слияние в `main` запускает деплой Timeweb; ветка сама по себе production не меняет.

| Данные | Канонический источник | Что не должно его подменять |
|---|---|---|
| Товар, размер/SKU, контент, категория, цена сайта | БД сайта, домен `admin` | Импорт названий/цен из СБИС |
| Свободный складской снимок и время актуальности | Интеграция СБИС, `inventory` | Локальный визуальный счётчик |
| Корзина покупателя/гостя | `internal/cart`, frontend `lib/cart.ts` | localStorage или отдельная корзина в PDP |
| Деньги и чеки | `payment`, подтверждённые ответы ЮKassa | Отображаемый клиентом статус или ручной email |
| Связи маркетплейсов | `product_external_ids`, рабочий каталог каналов | Совпадение названий или внешний артикул вместо SKU |
| Права сотрудника | `admin_users`, `admin.Can` | Email аккаунта |
| Новые файлы | `fileassets` и соответствующее S3-хранилище | Эфемерный диск контейнера |

## Настройки и окружение

Канонический перечень env — `internal/config/config.go`; подробные правила
бизнес-переключателей — `internal/settings/settings.go`. Документ группирует их,
но не копирует каждый числовой default и не утверждает, что секрет задан в production.

| Группа | Основные env / рабочие параметры |
|---|---|
| Runtime и БД | `DATABASE_URL`, `DATABASE_SSL_CA`, `DATABASE_SSL_VERIFY`, `PORT`, `HTTP_ADDRESS`, `STATIC_DIR`, `MIGRATIONS_DIR`, `SITE_URL`, `APP_ENV` |
| Сессии/идентификация | `AUTH_COOKIE_SECURE`, `AUTH_SESSION_DAYS`, `SMSRU_API_KEY`, bootstrap `ADMIN_EMAILS` |
| Доставка | `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`; `cdek.orders_enabled`, `cdek.packaging_season`, sender settings |
| Оплата | `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, налоговые параметры; `payments.enabled` |
| Коммуникации | `SMTP_*`, `MAIL_FROM*`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ORDER_CHAT_ID`, `VAPID_*`; `telegram.enabled` |
| Адрес/организации | `YANDEX_SUGGEST_API_KEY`, `DADATA_API_KEY`; отсутствие ключа не должно создавать ложное подтверждение адреса |
| Публичные фото | `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `STATIC_ASSETS_BASE_URL` |
| Приватные файлы | `PRIVATE_S3_*`, `FILE_STORAGE_MODE`; mock разрешён только isolated staging, `LOCAL_PRIVATE_FILES_DIR` только local development+mock |
| СБИС | `SABY_APP_CLIENT_ID`, `SABY_APP_SECRET`, `SABY_SECRET_KEY`, `SABY_POINT_ID`, `SABY_PRICE_LIST_ID` |
| WB/Ozon/Авито | `WB_API_TOKEN`, `OZON_CLIENT_ID`, `OZON_API_KEY`, `AVITO_*`; отдельные `CATALOG_WB_API_TOKEN`, `CATALOG_OZON_*` для нового publisher с fallback |
| Публикация каталога | `CATALOG_PUBLICATION_MODE=disabled/mock/live`; live дополнительно требует production и `CATALOG_PUBLICATION_LIVE_ENABLED=true` |
| Аналитика/SEO | `METRIKA_MP_TOKEN`, `analytics.metrika_id`, verification settings |
| Заказы/ценообразование | `orders.auto_cancel_hours`, отдельные версионируемые procurement pricing settings |

`saby.stock_enabled` удалён как ключ без runtime-потребителя. Отсутствие внешних
ключей не является основанием удалять предусмотренное поведение интеграции.
Для production обязательно проверить наличие `SMSRU_API_KEY`: текущий no-key
клиент подтверждает звонок заглушкой на первом опросе и подходит только для
контролируемого development/CRM. Наличие ключа на Timeweb этим аудитом не проверено.
Telegram также различается по окружению: development/staging используют
отключённый адаптер, а production требует корректные bot token/chat ID при старте.
`.env.example` теперь задаёт локальный development-профиль и содержит только
читаемые настройки; неиспользуемые параметры планировавшихся доставок и
`YOOKASSA_SEND_RECEIPT` удалены. Реальные секреты окружений этим не меняются.

Режим `disabled` публикации редактора не выключает закупочные действия:
это отдельный процесс со своей очередью. Старый exporter СБИС удалён.

| `staging-verification.yml` | Staging/manual: проверка изолированного кандидата и запись результата deployment |

Не обнаружено workflow, которое можно удалить только потому, что оно ручное:
ручные probe и fallback используются при инцидентах. Production monitor —
самостоятельная действующая задача, а не пережиток старого интерфейса.

## История БД и совместимость, которую нельзя удалять вслепую

В `legacy_archive` перемещены 13 финансовых таблиц, прежние staging photos/cards,
`product_creation_drafts`, `catalog_ai_enrichment_jobs` и одноразовый
`reservation_reset_audit`, а также завершённая история `catalog_saby_exports`. Миграции сохраняют байты,
JSON, исходные идентификаторы и отделяют архив от каскадного удаления рабочих
сущностей. Финансовые триггеры упаковки отключены; timestamps реальной отгрузки
сохранены. Архивирование очищает рабочую схему, но не освобождает диск.

Сохранены и объясняются данными, а не наличием старой кнопки:

1. Старый exporter СБИС удалён после production-проверки: 0 записей всего.
   Миграция повторно проверяет очередь под блокировкой, архивирует историю

## Доказательства и пределы аудита

Статический аудит связывает UI → HTTP → доменный метод → SQL/worker, учитывая
runtime, type-only и динамические импорты. Проверки выполняются на локальном коде,
моках и отдельной PostgreSQL; они не подтверждают пустоту production-очередей,
неиспользование API внешним клиентом или настройку секретов на Timeweb.

Production-срез 13 ноября 2026 подтвердил пустоту старой очереди СБИС и три
неотправленных manual-черновика. Старый exporter снят; черновики переносятся
неподтверждёнными в новую ценовую очередь, исходные записи сохраняются в архиве.
Подробные состояния и условия переноса — в
[legacy-process-retirement.md](legacy-process-retirement.md). Не удаляйте
неизвестные результаты текущей очереди публикаций. Не переписывайте уже
применённые SQL-миграции и не используйте `DROP ... CASCADE` для обхода зависимостей.

Повторная проверка после переноса цен выявила два поля без потребителей:
`procurement_action_batches.source` стал константой `procurement`, а
`catalog_editor_price_publications.old_value_minor` дублировал старую цену из
`legacy_archive.manual_price_items.old_value`. Следующая миграция удаляет их;
она сначала проверяет точное архивное происхождение каждой непустой старой цены.
`legacy_proposal_id` остаётся для связи с исходным предложением. Полезные payload,
fingerprint, mode, lease, claim token и состояния действующих очередей сохраняются.

Сохранены механизмы, которые легко ошибочно принять за остатки старой версии:

- `catalog_editor_link_history` заполняется SQL-триггером при смене внешней связи;
  отсутствие Go INSERT не означает отсутствие потребителя.
- `launch_hidden_extra_plant_variants` участвует в фильтрах витрины и оформления;
  связанные `launch_hidden_*_products` защищают объединение опубликованных товаров.
- `saby_catalog_merge.py` импортируется действующим `sync-saby.py`; ручные Saby
  workflows остаются аварийной синхронизацией и read-only диагностикой.
- `economics.unified.enabled` всё ещё принимается API настроек без ограничения
  «только true». Расчёт при false используется рабочими quote/calculator/plan
  путями и отдельными полями UI. Удаление альтернативной формулы требует отдельного
  решения о поддерживаемой конфигурации и миграции настроек.

Для следующей миграции удаления полей локально прошёл
`TestManualPricesMoveToEditorDraftsOnDatabase`: семь сценариев 212→213,
включая пустую старую историю и отказ для неизвестного архиву значения цены.
Тест сравнивает все оставшиеся поля рабочих и архивных строк до/после 213,
проверяет сохранение queued-команд и запрет кэшированного manual INSERT.
Это проверка отдельной PostgreSQL без внешних запросов, не применение к production.

Функция считается снятой только после согласованной очистки её UI, API,
worker/cron, конфигурации, источников данных, тестов, проверок и документации.
Если временно оставлен reconciliation/read path, запишите конкретную причину
и условие его последующего удаления вместо бессрочного комментария «legacy».
