# Идентичность товара и характеристики каталога

## Инварианты

1. Карточку товара сначала создают в СБИС. Её код вида `X...` — главный
   видимый бизнес-код в справочнике, документах и административных экранах.
2. Внутренний идентификатор варианта — неизменяемый SKU `FIC-000123`.
   Его выдаёт PostgreSQL sequence, менять SKU после вставки запрещает trigger.
3. Числовые `products.id`/`product_variants.id` остаются ключами связей в БД.
   URL продолжает использовать стабильный `products.slug`. Поэтому миграция
   SKU не меняет ссылки, корзины и строки существующих заказов.
4. Saby, Wildberries, Ozon и любой следующий канал — только mapping в
   `product_external_ids`. Внешний ID никогда не генерирует Ficusin SKU.
5. Старые значения `product_variants.sku` не теряются: они записаны как
   `provider=ficusin, id_type=legacy_sku` до назначения нового SKU.
6. Пустое значение интеграции не удаляет подтверждённый mapping и не затирает
   локальный контент. Исправленный или снятый артикул получает статус
   `legacy`, продолжает связывать исторические продажи и исчезает только из
   списка текущих артикулов.
7. У одного SKU может быть несколько артикулов Ozon/WB. В Wildberries
   пользовательским идентификатором является `vendor_code`; числовой `nmID`
   хранится как скрытый технический ключ для входящих продаж и вызовов API.

## Атрибуты

- `attribute_definitions` описывает код, тип, единицу, варианты значения и
  аудиторию (`customer` или `technical`).
- `category_attributes` задаёт обязательность, фильтр, PDP, важную плашку и
  порядок для категории. Дочерняя категория наследует схему предка; ближайшее
  определение имеет приоритет.
- `product_attribute_values` хранит JSONB-значение и источник.
- `GET /api/v1/admin/categories/{id}/attributes` отдаёт эффективную схему для
  category-driven редактора.
- При создании опубликованной карточки, смене категории/характеристик и
  повторной публикации backend проверяет все `is_required`. Старые карточки
  не снимаются с витрины массово: правило начинает действовать при их
  содержательном редактировании.
- Публичные API отдают только customer-атрибуты. `is_filterable` строит
  фильтры каталога, `show_on_pdp` — таблицу характеристик, `is_badge` —
  короткие плашки. Technical-поля в клиентский контракт не попадают.

Старые typed-колонки растений и упаковки пока сохранены для совместимости.
Триггеры зеркалируют их в новую модель независимо от того, какой код сделал
запись. Удалять legacy-колонки можно только отдельной миграцией после перевода
витрины, заказов, CDEK и всех импортов на `product_attribute_values`.

## Фотографии

`product_media.object_key` может временно содержать URL поставщика.
`media_mirror` связывает его с собственными `card` (600 px) и `large`
(1200 px) копиями в S3. Все клиентские и административные чтения выбирают
собственную копию через `COALESCE`; после зеркалирования недоступность Saby не
влияет на изображение. Очередь запускается сразу после старта приложения,
повторяет временные ошибки и ограничивает размер входного файла.
Миграция `045_retry_external_photo_migration.sql` один раз возвращает в очередь
только используемые Saby-фотографии без готовой собственной копии; успешные
mapping и локальные изображения она не затрагивает.
Загрузчик принимает исходники и redirects только с HTTPS-доменов Saby — URL
из интеграции не может использовать приложение для запросов во внутреннюю
сеть. Сводка полного состояния галерей доступна владельцам каталога через
`GET /api/v1/admin/catalog/media-health`.

## Добавление интеграции

Добавляйте mapping транзакционно вместе со связыванием товара:

```sql
INSERT INTO product_external_ids(product_id,variant_id,provider,id_type,external_id)
VALUES ($1,$2,'marketplace','offer_id',$3)
ON CONFLICT(provider,id_type,external_id) DO UPDATE SET
  product_id=EXCLUDED.product_id, variant_id=EXCLUDED.variant_id,
  updated_at=CURRENT_TIMESTAMP;
```

Не добавляйте новый внешний ID колонкой в `products` и не используйте его в
заказах. Колонки `saby_id` оставлены только как переходный read path.

В редакторе товара Ficusin/Saby mappings защищены от ручного удаления.
WB/Ozon/другие mappings меняются явно и транзакционно; конфликт внешнего ID
с другим товаром отклоняется, а не перепривязывает идентичность молча.

Saby sync сохраняет raw `attributes` в `saby_nomenclature.characteristics` и
переносит только allowlist известных кодов с корректным типом/enum. Пустой
supplier value ничего не стирает, а `source=local` всегда приоритетнее Saby.
