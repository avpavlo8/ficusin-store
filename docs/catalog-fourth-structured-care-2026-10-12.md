# Четвёртый пакет: структурированные поля ухода и диагностика объединения

Живой аудит после релиза #486: 324/324 SKU из PDF видны в 295 карточках, 26 вне списка скрыты. Публичные API 295/295 карточек ответили без ошибок. Без краткого описания и инструкций по уходу остаются 34 карточки, без Latin — 27, без полного описания — одна (#858). Отдельные поля `lightLevel` и `watering` отсутствуют у 44 карточек.

В 22 из этих 44 карточек уже есть конкретные рекомендации по свету и поливу в `careInstructions` и `passport`. Миграция `20261012_zzzzz_structured_light_watering_from_existing_care.sql` переносит смысл **только в пустые** структурированные поля для точных `product_code` и названия, если опубликованная карточка растения всё ещё содержит уход. Она не меняет текст, цену, остаток, размеры, фото, SKU и связи каналов. Два поля затем копируются штатным триггером в PIM `product_attribute_values`. Для составных товаров (флорариум, композиции) эти метки отражают уже опубликованный уход для конкретной карточки и требуют проверки состава владельцем.

Предпросмотр объединения Raven 112/113 после ботанической правки #486 больше не блокируется Latin. Текущий блокер — различие нормализованных атрибутов, хотя видимые поля админки совпадают. Код предпросмотра теперь сообщает точный `attribute_definitions.code` и значения по внутренним ID, чтобы отличить реальный конфликт ухода от старого атрибута размера. Ни одна реальная карточка этим пакетом не объединяется. Следующий шаг — повторить предпросмотр в production и разрешить конфликт на основании показанных значений.
