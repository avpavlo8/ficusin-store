# Как работать с этим репозиторием

Памятка для агентов и новых разработчиков. Здесь то, что не видно из кода
сразу и на чём легко потерять время.

## Что это

Интернет-магазин комнатных растений «Фикусин» (ficusin.ru). Один Docker-образ:
Go отдаёт `/api/v1/*` и статику собранного фронтенда.

```
frontend/   React + TypeScript + Vite
public/     статика и файлы PWA (манифест, sw.js, иконки)
backend/    Go, HTTP API
timeweb/    SQL-миграции PostgreSQL
e2e/        Playwright-тесты вёрстки (iPhone, Android, десктоп)
docs/       документация и аудиты
```

## Как это развёрнуто

Timeweb Cloud App Platform, приложение `229223`. **Мерж в `main`
автоматически запускает деплой** — отдельного шага выкладки нет.

Миграции применяются самим приложением при каждом старте
(`migrate.Apply` в `cmd/api/main.go`), поэтому новый `.sql` в
`timeweb/migrations/` попадает в базу сразу после деплоя. Отдельно накатывать
ничего не нужно. Миграции идут по алфавиту имени файла.

## Переменные окружения

Задаются в панели Timeweb, в репозитории их нет. Пустое значение обычно
означает «функция выключена», а не ошибку:

| Переменная | Что ломается, если пусто |
|---|---|
| `DATABASE_URL` | приложение не стартует |
| `SMSRU_API_KEY` | вход по звонку работает в режиме заглушки |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ORDER_CHAT_ID` | уведомления о заказах не уходят |
| `YANDEX_SUGGEST_API_KEY` | поле адреса работает как обычный ввод |
| `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET` | доставка СДЭК скрыта из оформления |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | оплата картой скрыта из оформления |
| `YOOKASSA_SEND_RECEIPT` | `1` — чеки печатает ЮKassa; пусто — своя касса |
| `SITE_URL` | адрес возврата после оплаты, по умолчанию `https://ficusin.ru` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `MAIL_FROM` | письма покупателям не отправляются |
| `ADMIN_EMAILS` | некому выдать права владельца на пустой базе |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | push-уведомления выключены, кнопка в кабинете не показывается |
| `WB_API_TOKEN` | подтверждённые цены WB остаются со статусом «API не подключён» |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | подтверждённые цены Ozon остаются со статусом «API не подключён» |
| `SABY_APP_CLIENT_ID`, `SABY_APP_SECRET`, `SABY_SECRET_KEY` | backend не может проверить сервисную сессию Saby |
| `SABY_POINT_ID`, `SABY_PRICE_LIST_ID` | диагностика Saby использует точку 278 и прайс 6 по умолчанию |

**Все внешние ключи — только из окружения.** Была ещё таблица
`integration_credentials` с RSA-шифрованием; ключа расшифровки в Timeweb не
оказалось, и из-за этого молча отвалились сначала Telegram, потом СДЭК.
5 августа 2026 механизм удалён целиком. Новые интеграции подключайте
переменной окружения и обязательно предусматривайте поведение при пустом
значении.

## Архитектура бэкенда

```
cmd/api/main.go          сборка зависимостей
internal/httpapi/        HTTP-слой: роутер, обработчики, валидация
internal/auth/           сессии, профиль, вход по звонку
internal/order/          оформление заказа, уведомления
internal/admin/          панель управления, роли и права
internal/catalog/        витрина
internal/saby/           приём каталога из СБИС
internal/integration/    внешние сервисы: SMS.ru, CDEK, Telegram
```

Правило: HTTP-слой валидирует вход и переводит ошибки в коды ответа, бизнес-логика
живёт в доменных пакетах и про HTTP не знает.

## Вход по звонку — как он устроен

Пароля нет. Схема SMS.ru «звонок от пользователя»:

1. `POST /auth/request-code` → SMS.ru выдаёт номер и `check_id`, строка
   пишется в `call_checks`.
2. Покупатель звонит на выданный номер со своего телефона.
3. Фронт раз в 3 секунды дёргает `POST /auth/verify-code` с `checkId`.
   `202` — ждём звонка, `200` — вошли, `404`/`409` — не тот сценарий.

Тонкости, на которых уже спотыкались:

- **`check_status` от SMS.ru приходит числом, а не строкой.** Схема
  `/code/call` устарела и звонков не делает — не возвращайтесь к ней.
- **Фоновый опрос не должен слать данные формы.** Иначе аккаунт создастся с
  недописанным именем. Регистрация — только по явной отправке формы, поле
  `flow` (`login`/`register`) обязательно.

## Права в панели управления

Роль берётся **только из `admin_users`** по `customer_id`. Совпадение email
ничего не даёт: почта нигде не подтверждается, а владелец аккаунта меняет её
сам из профиля.

`ADMIN_EMAILS` работает один раз — при старте, если в `admin_users` нет ни
одного активного администратора (`admin.BootstrapOwners`). Дальше роли
раздаёт владелец из панели.

## Персональные данные

Два правила, которые нельзя нарушать:

- **В Telegram не уходят персональные данные.** Только номер заказа, состав,
  суммы и способ получения. Telegram — иностранный сервис, отправка туда
  контактов = трансграничная передача. Тест
  `TestTelegramMessageOmitsPersonalData` это стережёт.
- **Согласие фиксируется на сервере.** Таблица `consent_events`, пакет
  `internal/consent`. Запись идёт в той же транзакции, что и заказ или
  регистрация — заказа без записи о согласии существовать не может. Меняете
  текст оферты или политики — поднимите `consent.Version`.

## PWA и уведомления

Сайт устанавливается на домашний экран: `public/manifest.webmanifest`,
`public/sw.js`, иконки там же. Правила кэша заданы в service worker и
намеренно осторожные — `/assets/*` вечно (в имени хэш), страницы только по
сети, `/api/**` не кэшируется никогда. Меняете стратегию — поднимите
`VERSION` в `sw.js`, иначе старый воркер останется у людей.

Push сделан на стандартной библиотеке Go без внешних зависимостей:
`internal/webpush` (RFC 8291 + VAPID), `internal/notify` (подписки и
рассылка). Тест `TestEncryptedPayloadCanBeReadByTheBrowser` расшифровывает
сообщение так же, как это делает браузер — если шифрование поедет, тест
упадёт. На iPhone уведомления приходят только если сайт добавлен на
домашний экран; это ограничение Safari, а не наше.

## Частые грабли

- **`customers.email` может быть NULL.** Пароля нет, почту указывают не все.
  В `SELECT` оборачивайте в `COALESCE(c.email, '')`, иначе скан в `string`
  уронит запрос. На этом уже падал `/auth/me`.
- **`PUT /account/profile` заменяет запись целиком.** Отправка одного поля
  обнулит остальные. Форма шлёт все поля сразу; при ручных запросах помните
  об этом.
- **Фото профиля уменьшает браузер** до 256×256 JPEG перед отправкой.
  Сервер только проверяет размер и MIME. Файловая система контейнера
  эфемерная — храните в базе, туда же положен аватар.
- **Заказ резервирует остаток.** `reserveStock` блокирует строки
  `inventory` и увеличивает `reserved_qty`; отмена заказа в панели
  возвращает количество обратно (`releaseStock`, защищено
  `orders.stock_released_at`). Добавляете новый путь создания заказа —
  не забудьте про резерв, иначе будет пересорт.
- **Корзина читается сразу в начальное состояние** `useState`, а не из
  эффекта. Когда чтение жило в `useEffect`, эффект сохранения успевал
  отработать раньше и затирал сохранённую корзину пустой — со стороны это
  выглядело как «корзина иногда сама скидывается».
- **Габариты упаковки — это цена доставки.** СДЭК берёт больший из весов,
  реального и объёмного (Д×Ш×В÷5000), так что за растение платим по коробке.
  Поля `package_*_cm` и `package_weight_grams` заполняет менеджер в карточке;
  фоновая синхронизация с СБИС их не трогает. Правило сборки общей коробки —
  `integration.CombineParcels`, проверено тестами.
- **Оплаченным заказ делает только запрос к ЮKassa.** Уведомление на
  `/api/v1/payments/yookassa/webhook` не подписано и доступно кому угодно —
  это повод сходить и спросить статус, а не источник правды. Сумма меньше
  суммы заказа оплатой не считается.
- **Настройки магазина живут в таблице `settings`** и меняются в панели без
  перезапуска: выключатели интеграций для тестов, срок автоотмены, данные
  отправителя. Секретов там нет и быть не должно — ключи только в окружении.
- **Письма уходят из очереди `outbox`, а не из запроса.** Строка пишется в
  той же транзакции, что и заказ, поэтому обещанное письмо не потеряется при
  перезапуске. Неудачная отправка считается в `attempts` и повторяется, после
  пяти попыток бросается. Медленный SMTP никогда не тормозит оформление.
- **Передача в СДЭК выключена по умолчанию.** Включается настройкой
  `cdek.orders_enabled`. Иначе тестовый заказ станет настоящей посылкой.
- **Заказ никогда не падает из-за доставки.** Нет габаритов, СДЭК молчит,
  покупатель попросил одну коробку — цена не считается, ставится
  `orders.delivery_fee_pending`, и заказ оформляется дальше. Добавляете новый
  путь расчёта — не вздумайте возвращать оттуда ошибку в оформление.
- **Счётчики корзины и избранного** живут в `localStorage`. Шапка читает их
  сама, если ей не передали значения; страницы со своим состоянием передают
  явно. При изменении из своего кода шлите
  `window.dispatchEvent(new Event(STORAGE_EVENT))`.

## Проверки

CI (`.github/workflows/ci.yml`) гоняет четыре задачи на push и на PR:

- `frontend` — `npm ci`, `npm run lint`, `npm run build`
- `layout` — Playwright-тесты вёрстки на iPhone, Android и десктопе
- `backend` — `go test ./...`, `go vet ./...`, `go build ./cmd/api`
- `image` — сборка Docker-образа

Полезно знать заранее:

- **Линтер фронтенда падает на `setState` прямо в теле `useEffect`**
  (правило `react-hooks/set-state-in-effect`). Переносите вызов в обработчик
  или в таймер.
- **Тесты вёрстки живут в `e2e/`** — отдельный проект со своим
  `package.json`, ставится через `npm install` (не `ci`, lock-файла нет).
  Гоняются против собранного бандла на `vite preview`, API замокан в
  `e2e/tests/helpers.ts` — при изменении формата ответа поправьте моки.
  Локально: `npm install && npx playwright install && npm test` в `e2e/`.
- **Интерфейс `authService` в `httpapi` реализуют четыре заглушки в тестах**
  (`router_test.go`, `auth_test.go`, `admin_test.go`, плюс встроенная в
  `orders_test.go`). Добавили метод в интерфейс — обновите все.

## Единый стиль интерфейса

Личный кабинет и панель управления используют **одну и ту же вёрстку**:
`account-page` → `account-shell` → `account-sidebar` + `account-content`.
Отличается только содержимое правой колонки. Новые разделы делайте в этом же
каркасе, не заводите отдельный.
